# Evidence bundle contract 0.3

> Historical scope note (2026-10-11): this contract records the earlier 0.3 synthetic path. For the current envelope, use `PROJECT_BUNDLE_V07.md`; the older schema remains available for reproducibility.

Run `yk-evidence contract-run --output runs --run-id contract-001 --seed 42`, then `yk-evidence verify runs/contract-001`. The command first produces the integrated raw evidence and then emits a contract layer from that same run. It refuses to overwrite a run ID.

The required contract artifacts are `run_metadata.json`, `input_manifest.json`, `provenance.json`, `lineage.json`, `retrieval_evidence.json`, `risk_scores.csv`, `model_metadata.json`, `metrics.json`, `drift_report.json`, `stress_test_results.csv`, `release_gate.json`, `review_report.html`, and `bundle_manifest.json`. The last file lists the SHA-256 hashes of every other artifact; it cannot hash itself.

From product version `0.3.0rc3`, `decision_impact.json` is also required. It records the held-out confusion matrix at each training-selected threshold, 95% Wilson rate intervals and three explicitly hypothetical workload/cost scenarios. The verifier recomputes it from raw `benchmark.json` predictions and the fixed policy assumptions in code. Removing it from the manifest, or changing a scenario number and rehashing, fails verification. Older fixed rc1/rc2 bundles remain readable without this file. See `DECISION_IMPACT_PROTOCOL.md`.

`verify` checks exact file membership and hashes before semantic checks. It cross-checks the run ID, schema, source classification, code hash and seed against the raw run record; input manifest entries against the raw files; retrieval answer, citations and source hash against the finance memo and snapshot; risk rows against raw predictions and source transaction labels; and release-gate conditions against the underlying evidence. It independently derives the declared chronological 75/25 split from source-row order and checks every model's held-out IDs and prediction count. It also recomputes the SEC arithmetic, held-out average precision, F1 at 0.5, recall at the recorded training-selected threshold, actual held-out false-positive rate, confusion counts and saved stress-scenario metrics. A file edited and rehashed in the manifest can still fail semantic verification.

With `--graph-epochs N`, the optional PyTorch Geometric GraphSAGE run is written as `graphsage_evidence.json` **before** the final bundle manifest is emitted. It uses the same source rows and test IDs as the four baselines but a stricter training-only graph context, so the resulting scores are an additional synthetic experiment rather than a controlled architecture ranking. Its file hash, input-manifest link, held-out labels/scores and reported AP/F1/prevalence are verified. The default core run has no GraphSAGE dependency. A review submitted in the local page is written separately to `runs/reviews/RUN_ID.jsonl`; each record links to the bundle manifest and previous record hash, and `verify` validates the sidecar if present. This local journal is not a signature or proof of reviewer identity and never changes the model release gate.

With both `--transactions-csv` and `--transactions-metadata`, a rights-declared synthetic CSV is normalized before a run directory is created. Its exact bytes and operator-supplied metadata are copied into the bundle along with `import_profile.json`. The verifier reparses the source CSV, checks its declared SHA-256, source-row ordering and labels, and recomputes the profile and model metrics. The metadata is an **operator declaration**; verification cannot prove the license or data origin independently. The import path has no repeated-seed stability claim. See `docs/IMPORTING_SYNTHETIC_TRANSACTIONS.md` for required fields and limits. The default generated mode remains the regression baseline.

The machine-readable Draft 2020-12 schema is packaged at `src/yk_evidence/assets/schemas/contract_0_3.json`. Its `x-artifacts` map selects a `$defs` schema for each of ten JSON files, and `verify` uses `jsonschema==4.26.0` to check those structures and types before semantic checks. CSV headers and row relationships are enforced by the verifier rather than JSON Schema. The schema does not by itself prove data provenance or independent authenticity.

The SEC evidence is a fixed public two-fact extract with citations and deterministic arithmetic. `retrieval_evidence.json` records structured-fact mode and `formal_rag=false`; it does not claim live retrieval or LLM use. Transaction rows are generated, and their scores cannot support claims about real fraud detection. A blocked release gate is expected. The verifier does not independently reconstruct the fitted models or the threshold selected from training scores, which are not stored row by row. Local hashes and consistency checks are not an external signature or timestamp; a party replacing every source and result together could create a self-consistent new bundle. The JSON Schema covers contract structure but independent authentication remains outside the current design.
