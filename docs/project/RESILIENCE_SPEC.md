# Prediction resilience specification — 0.6.0rc1

This extension corrects two observed score-delivery faults without altering the existing 0.10 maximum AP-loss criterion. Existing unprotected 0.5 controls remain visible. Inference inputs and calibrated probabilities are bound to a local producer receipt including model identity, batch context and transaction row IDs. Accidental downstream score corruption, duplicate/missing IDs and stale context trigger a bounded retry; persistent failures quarantine the model and select a policy frozen from validation for the healthy subset. All-model loss produces no decisions. The full healthy route retains the existing fusion and threshold.

Validation fallback uses the existing chronological first half to select the best average-precision single model for each nonempty available subset, with budget recall and stable name order breaking ties; its own threshold is frozen on the second validation half. The production scoring seam never receives test labels. At least two healthy models are required for availability; otherwise all rows are withheld. This is a documented software policy, not a bank staffing or regulatory standard.

Fixed score-delivery scenarios are clean, strongest_model_dropout, one_model_row_roll, eight_bit_quantization, persistent_strongest_model_dropout, reordered_records, stale_context, and all_models_unavailable. First-attempt transient faults occur after producer receipt creation, preserving a verifiable control point; persistent faults recur on retry. Retry recomputes the actual model on the same feature batch, at most two calls per model. Evidence retains failed deliveries, receipts, final scores, row identity, call counts, route, fallback choice and separate post-hoc quality outcomes. Original controls are score-space probes, not changed economic features.

Receipts detect accidental post-production corruption within one local process. They are not cryptographic authentication of a remote model, independent signatures, model-calibration guarantees or protection against corruption before receipt creation. No labels are used to detect faults. If a producer consistently returns plausible wrong probabilities and a matching receipt, the system cannot certify them as true. Ordinary bundle verify/serve never deserializes model binaries.

The schema 0.6 random forest runs with `n_jobs=1`: the earlier two-worker forest occasionally changed the final bits of probability sums across calls on the same real feature batch. Exact receipts require stable producer output in this deterministic local experiment. This setting is recorded and checked against the schema, and current capacity measurements include its cost. Legacy schema 0.5 retains its recorded two-worker specification.

Acceptance requires actual four-model fits and actual recovery callbacks, both original transient scenarios meeting the unchanged AP-loss criterion, persistent failure outcomes reported honestly, no decisions under complete failure, tamper rejection after recomputing file hashes, old bundle compatibility, reproducible raw evidence and engineer installation/UI validation. Historical ULB test observations remain retrospective; software-fault recovery does not establish prospective business effectiveness.
