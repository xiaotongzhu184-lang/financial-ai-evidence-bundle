# Tabular research evaluation protocol (v0.4)

This protocol evaluates the public ULB/Worldline credit-card CSV as an **anonymized tabular historical benchmark**. It does not evaluate the older generated transaction graph, a live fraud system, or financial-statement retrieval. The data fields are `Time`, `V1`–`V28`, `Amount`, and `Class`. `Time` is relative; no calendar date or UTC is inferred. The file supplies no account, merchant, or network identifiers, so no graph edges are invented. Raw licensed CSV bytes stay outside the software/evidence archive.

## Frozen split and model selection

1. Read every row of the ULB CSV; require the exact column order, numeric finite time and features, `Time >= 0`, and labels `Class ∈ {0,1}`. `Amount == 0` is permitted. Preserve the original CSV physical line number as `row_id`.
2. Stable-sort by relative time. Start partition cuts at 55%, 70%, and 85% of the row count and move each cut **forward after the last equal timestamp**. The result is train, calibration, validation, and untouched test partitions. Each partition must have both classes; calibration must have at least two rows per class.
3. Fit a median imputer on train only for all models. Fit a standard scaler on train only for logistic regression. Fit these **fixed** scikit-learn models with the specified seed: balanced logistic regression (`liblinear`, 300 iterations); balanced random forest (60 trees, depth 12, leaf size 4, sqrt feature sampling, 2 jobs); histogram gradient boosting (80 iterations, 15 leaves, leaf size 10, learning rate 0.08, early stopping off). Both calibration and model selection use data held out from training.
4. Fit Platt sigmoid calibration on the separate calibration partition with the model frozen. Use the public `CalibratedClassifierCV(FrozenEstimator(...), method="sigmoid", cv=2, ensemble=False)` path in the pinned scikit-learn environment; the frozen model is not refit on calibration rows. Save raw probability, calibration input (decision function or probability), sigmoid parameters, and calibrated probability for every calibration, validation, and test row.
5. Select one model by **validation average precision**, with the fixed model order breaking exact ties. For each model, take the validation negative score at rank `floor(ceiling × negative_count)` in descending order as its threshold. Decisions use strict `score > threshold`, so tied negative scores cannot exceed the requested ceiling. Default ceiling: 0.01. The test set does not influence either selection or threshold.
6. Report calibration, validation and test calibrated average precision, Brier score, precision, recall, F1, FPR, confusion counts, and Wilson 95% intervals for recall/FPR/precision. Derive review workload from the same confusion counts: `alert_count = TP + FP`, `alerts_per_10000 = 10000 × (TP + FP) / rows`, and `missed_cases = FN`. Record `monetary_cost_estimated = false`. Also report raw uncalibrated average precision and Brier on each partition so the effect of calibration is visible. Average precision is named as such; it is not an interpolated PR-AUC. Undefined single-class partitions fail before training rather than receiving invented metrics.

## Stress and load measurements

The selected fitted model and calibrator remain frozen. Three deterministic scenarios are applied to test **features**, retaining the original test labels: V1/V2 missing in 10% of rows, V1/V2 Gaussian noise in 10% of rows with standard deviation 0.1 times the original test-feature standard deviation, and `Amount × 1.2` in all test rows. The 10% selection is fixed by `seed + 1109`; a scenario's changed-row count, per-row score, metrics and status are archived. The demonstration status uses an average-precision drop ceiling of 0.10 carried forward from the v0.3 stress replay before the v0.4 final run. This is a declared research probe, not a production threshold. Feature perturbations do not create independently adjudicated fraud labels. The use of test-feature standard deviation to set the noise scale is a scenario design choice; it does not fit or tune the model.

Capacity runs score repeated batches of the same test features at 100,000 and 1,000,000 rows by default, with batches no larger than 8,192. They measure elapsed time, scores/second, stream hash and process peak RSS when the operating system exposes it. On macOS RSS is recorded in bytes; on Linux `ru_maxrss` is KiB and is converted to bytes. On Windows, where the POSIX `resource` module is unavailable, peak RSS is explicitly `null` with source unit `unavailable`; no memory value is invented. The environment records platform, architecture, CPU count, Python/scikit-learn versions and the 2-thread compute limit. These repeated rows count as **zero new independent accuracy observations**. Throughput and peak memory are machine-specific measurements, not service-level guarantees.

## Evidence contract

`evaluate_dataset(csv_path, metadata, output_dir, seed=42, fpr_ceiling=.01, load_rows=1_000_000)` writes to a temporary sibling directory and finalizes only after all files and `evaluation_manifest.json` are written. A caller may pass a nonexistent destination or an existing **empty** staging directory. A nonempty destination is never overwritten. Required source metadata: `classification`, `source_url`, `license_status`; `source_sha256`, if supplied, must match the read CSV. The final bundle contains:

| File | Evidence |
| --- | --- |
| `evaluation_summary.json` | Source hash/metadata, exact split counts and relative-time ranges, config, fitted model parameters, calibration map, model selection, raw and calibrated metrics, stress/load links, environment and limits. |
| `evaluation_predictions.csv` | Calibration/validation/test row IDs, relative time, labels, raw and calibrated scores, calibration inputs, decisions for **all three models**. |
| `evaluation_stress.json` | Baseline and per-scenario scores/metrics, changed-row counts and AP-drop statuses. |
| `evaluation_capacity.json` | Repeated-feature workloads, timings, throughput, score-stream hashes, RSS units/bytes and machine context. |
| `model_<id>.joblib` | Fitted estimator and calibrator state for trusted local reproduction. Never load these from an untrusted bundle. |
| `evaluation_manifest.json` | SHA-256 of each preceding artifact plus external source CSV hash. |

`verify_evaluation(output_dir)` hashes the files and checks prediction membership, source row IDs within the CSV line-number range and unique across calibration/validation/test, time order, cross-model row/label links, per-row calibration formula, validation thresholds, raw/calibrated metrics, selected model, the exact three declared stress scenarios and changed-row counts, stress metrics/status, and the exact load workload sizes and capacity arithmetic. It **does not unpickle** the model files. Edits to a score, threshold, calibration parameter or metric followed by rebuilding the file hashes fail these semantic checks. This is internal consistency checking, not an independent signature: a coordinated adversary with control of every artifact can construct a different self-consistent bundle. Independent source authentication and fitted-model reproduction require acquiring the source CSV by its recorded URL, confirming its SHA-256, and rerunning the pinned code/environment.

## Interpretation

The dataset is historical and anonymized, with unknown original label-adjudication details and no institution-specific costs or current operational population. Treat all values as historical benchmark estimates. At a 1% FPR ceiling, even a strong average precision may yield many false alerts; report actual false-positive counts, precision, and the derived alert volume per 10,000 historical rows. Alert volume is a workload count, not an estimate of review hours or monetary cost: the benchmark contains no measured handling time, unit review cost, or institution-specific alert policy. Compare only models trained and evaluated under this same ULB protocol. Do not compare their scores with the earlier 400-row generated graph fixture as if the datasets measured one population. No financial, regulatory or production impact follows from benchmark metrics alone.

The sigmoid map is monotonic in its input, but a raw `predict_proba` can numerically saturate at exactly 0 or 1 while the underlying decision function retains distinct values. A change in average precision between stored raw and calibrated probabilities can therefore reflect the breaking of raw-probability ties. Do not describe such a difference as a newly learned ranking capability without checking the saved score distributions.
