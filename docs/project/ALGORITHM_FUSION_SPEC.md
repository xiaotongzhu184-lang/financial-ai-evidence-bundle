# Algorithm upgrade specification — 0.5.0rc1

## Goal
Add a runnable, verifiable challenger/ensemble experiment to the existing project: four fitted models including XGBoost, bounded review-queue selection, honest ablations and drift/stress evidence. Continue to serve legacy 0.3/0.4 bundles unchanged. Use mature packages with exact provenance. This specification defines a local research and engineering-review candidate.

## Protocol frozen before new results
Reuse the 55/15/15/15 chronological ULB split and preprocessing from evaluation.py. Train the same three v0.4 baselines and one fixed XGBoost challenger (hist, 160 trees, max_depth=4, learning_rate=.05, subsample=.8, colsample_bytree=.8, min_child_weight=5, reg_lambda=5, n_jobs=2, random_state=seed, scale_pos_weight=sqrt(train_negative/train_positive)). No early stopping and no test tuning. Calibrate each on the original calibration period using FrozenEstimator sigmoid. All input scores are probabilities; final fused score is a convex probability mixture, not a newly calibrated probability guarantee.

Split validation chronologically 50/50 with equal-time groups intact: tune weights on first half, freeze an empirical ALL-ROW review-budget threshold on second half. Each needs both classes. Tuning objective: maximize the MINIMUM recall at a hard top-floor(budget*n) review budget across two chronological halves of the tuning period; then overall average precision; then lexicographic deterministic weight tuple. Weight candidates: all nonnegative 4-model weights on a quarter-step simplex (35 candidates). Keep every candidate objective in evidence. Capacity policy at test: first threshold by frozen policy-half score quantile, then retain at most floor(budget*n) highest scores, using row_id ascending on ties. Report threshold alerts, reviewed, deferred, TP/FP/FN, budget utilization. Default budget .005. This budget is a documented scenario, not institution-specific staffing capacity. A threshold-only queue and hard-cap queue are both visible.

Ablations: each of four single models, equal-weight fusion, validation-selected best single, robust weighted fusion (selected may collapse to one model; disclose). Raw per-model/calibrated scores, calibration inputs/maps and per-partition identities are retained. Save sample disagreement stddev. Test labels NEVER enter fit_fusion or policy selection. Previously viewed ULB final period is explicitly retrospective exploratory comparison, not fresh confirmation.

Retain the upstream copyright/license and record the source file hash plus local changes. This is source-derived reuse, distinct from calling the XGBoost package. The upstream helper currently pools reference/current data for Sturges bins; do not label it reference-frozen. Our adaptation must fit bin boundaries only on the validation policy half, serialize them, and apply unchanged to test windows. Declare smoothing and normalization explicitly; report bin counts and per-bin PSI contributions so a verifier can reconstruct the result. Do not claim equivalence to the original helper after changing binning/smoothing.

Produce three chronological test windows with equal-time groups preserved, deterministic boundaries and explicit insufficient-data handling. Reference data never includes test rows. Each window reports sample count/time range, PSI and its contributions, threshold candidates, reviewed/deferred counts and budget utilization using the same queue policy as the rest of the project. Identify whether queue capacity is evaluated per window or over the full test horizon; never substitute computational batch boundaries for operational windows. Keep threshold-only and capacity-limited outcomes separate. A PSI review threshold is a declared demonstration policy, not evidence of model failure or a validated institution alert limit. Monitoring consumes frozen scores and must not refit models, calibration, fusion weights or operating thresholds.

Fraud Detection Handbook time-aware assessment and Precision@K are methodological references only in this implementation. ULB has no customer/card IDs or confirmed label-arrival times, so do not transplant card aggregation/removal or delayed-feedback behavior under transaction-row aliases. Record this data-model mismatch as the primary reason the card-level implementation is not adopted.
