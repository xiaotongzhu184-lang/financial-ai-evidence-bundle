# Development Data Card

> Historical scope note (2026-10-11): this card records the earlier 0.1–0.3 synthetic path. For current 0.7 onboarding, use the repository README and `PROJECT_BUNDLE_V07.md`. The separate ULB source boundary is documented in `ULB_DATA_ACCESS.md` and `TABULAR_EVALUATION_PROTOCOL.md`.

## Financial source

The project freezes two USD revenue facts for Microsoft FY2024 and FY2025, both cited to SEC 2025 Form 10-K accession `0000950170-25-100235`. The JSON extract records the official Company Facts endpoint, the filing URL, retrieval time, raw response hash, taxonomy concept, periods and values. It supports a narrow arithmetic memo only. It does not represent an evaluated financial question-answering corpus.

## Transaction source

In the default run, all transaction rows are generated by original project code with an explicit seed. Every nineteenth row injects a recurring synthetic customer/merchant pattern; its label is assigned by construction. No person, merchant or payment is real. There is no employer data and no anonymized customer data. The dataset permits a reproducibility and pipeline demonstration but cannot establish real-world fraud detection performance.

An optional importer accepts a local, rights-declared **synthetic** CSV with transaction ID, timestamp, customer, merchant, amount and binary label. It retains the exact source bytes, operator metadata, SHA-256 and a derived row/label/time/amount profile. The software checks structure and hash but cannot authenticate license, source or label meaning. No independently licensed third-party transaction dataset is shipped with this project; a test fixture generated by project code checks the importer only. Private inputs and their run bundles must not be published without separate rights review.

## Known limitations

Default generated labels are causally linked to the generator's pattern. The network structure is simple, and a chronological holdout from the same generator is not an external validation set. Imported synthetic files can have different units, label definitions and distributions; the fixed amount rule and sample metrics are exploratory until adapted and validated for that source. Publishing any metric must include classification, source/hash, seed, row count, split, label definition and raw prediction file. The release gate stays blocked for synthetic-only evidence.
